## Rules for this file
1. Read it at the start of every session, before any build work (pointer in `CLAUDE.md`, section 0).
2. Status is one of: **NOT STARTED**, **IN PROGRESS**, **DONE**, **BLOCKED**. A row is **DONE only with evidence** (commit, test name, screenshot path). Anything partly done stays IN PROGRESS and says what is missing.
3. **Never delete a row.** A row that no longer applies is marked **SUPERSEDED** with the reason and the date.
4. "Verified on demo" is **yes** only after the owner (or an operator) has confirmed the behaviour on demo.ogevia.com. Local tests and screenshots never set it to yes. As of this writing nothing has been deployed to demo, so every row is **no**.
5. **Deploy rule (owner, 2026-11-10, replaces any per-milestone deploy):** demo only, never production. Preferred: automated demo-only deploys through GitHub Actions and AWS OIDC, **after the owner approves** `docs/aws/DEMO_AUTODEPLOY_PROPOSAL.md` (nothing is created in AWS before that). If automation is not approved or not feasible: no per-milestone deploys; build everything, then ONE demo package with copy-paste steps when all rows are complete. Until then every row stays "verified on demo: no".
6. **Mockup is frozen** as the approved design reference (`docs/ux/mockup/ogevia-redesign-mockup.html`, approved 2026-11-10). It is not maintained in parallel with the build; each milestone report lists where the build deviates from it.
7. **Per-milestone preview (R31):** a downloadable single-file clickable preview of the real app code on synthetic data, labelled with the commit SHA and a short change list.
8. Distinguish proposed, implemented, tested, deployed (`CLAUDE.md` section 0). "Implemented locally" is never "deployed".
